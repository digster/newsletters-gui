# 2026-03-08: Initial Implementation

## What was done
- Scaffolded Tauri v2 project with vanilla JS frontend (no bundler)
- Implemented Rust backend: `db.rs` (SQLite + FTS5), `parser.rs` (YAML frontmatter), `commands/` (scan, emails, search, state)
- Implemented frontend: three-panel layout, sidebar, virtual-scrolled email list, iframe email viewer, Cmd+K search modal
- Ported design system from newsletters-github (CSS custom properties, dark mode, typography)
- Successfully indexed 13,641 emails across 65 labels in <2 seconds (release mode)
- FTS5 full-text search with snippet highlighting working

## Key bugs found & fixed
1. **PRAGMA journal_mode = WAL** returns a result row — can't use `execute_batch()`, must use `query_row()`
2. **UTF-8 slicing panic**: `body[..2000]` can split multi-byte chars (smart quotes) — fixed with `is_char_boundary()` check
3. **FTS5 DELETE hang**: External content FTS5 tables (`content='emails'`) can't be cleared with `DELETE FROM emails_fts` — must DROP and recreate
4. **Indexing architecture**: All file I/O must happen BEFORE acquiring the DB mutex lock to prevent blocking other Tauri commands

## Architecture notes
- SQLite DB stored at `~/Library/Application Support/com.newsletters.gui/newsletters.db`
- WAL mode for concurrent reads during writes
- FTS5 with porter stemming + unicode61 tokenizer
- Virtual scroll renders only visible rows (~30) for 14K+ email lists
- Frontend components communicate via custom DOM events (nav:change, email:select, search:navigate)
